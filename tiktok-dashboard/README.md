# tiktok-dashboard

Раз в час отправляет ссылки на ваши TikTok-аккаунты стороннему Telegram-боту
**от лица вашего личного Telegram-аккаунта** (а не через отдельного бота —
это обязательно, потому что обычный бот не может первым написать другому
боту, пока тот не нажал `/start`). Дожидается текстового ответа этого бота
по каждой ссылке и показывает всё в веб-дашборде.

## ⚠️ Важно

- Для отправки используется MTProto-клиент ([teleproto](https://docs.teleproto.dev),
  активно поддерживаемый форк GramJS), который логинится как обычный
  пользователь Telegram. Автоматизация
  личного аккаунта технически возможна, но формально не приветствуется
  политикой Telegram — при слишком частой/массовой рассылке аккаунт может
  получить временное ограничение. Скрипт шлёт сообщения строго
  последовательно с паузой (`DELAY_BETWEEN_SENDS_SECONDS`), не увеличивайте
  частоту без необходимости.
- `TG_SESSION` (строка сессии) даёт **полный доступ** к вашему аккаунту —
  это как пароль. Никогда не публикуйте её и не коммитьте в git (файл
  `.env` уже в `.gitignore`).
- Дашборд по умолчанию открыт всем, у кого есть URL — обязательно задайте
  `DASHBOARD_USER`/`DASHBOARD_PASSWORD` перед деплоем.

## Как это работает

```
tiktok-dashboard/
  src/
    login.js       разовый интерактивный логин личного аккаунта → TG_SESSION
    telegramUser.js MTProto-клиент: отправка ссылки боту + ожидание ответа
    dispatch.js     один цикл рассылки по всем активным аккаунтам
    scheduler        (внутри server.js) — cron-задача раз в час
    server.js       Express: API + отдаёт статичный дашборд из public/
    routes/accounts.js  CRUD аккаунтов и история отправок
  public/           дашборд (чистые HTML/CSS/JS, без сборки)
```

Цикл рассылки (`dispatch.js`) идёт по активным аккаунтам **последовательно**:
отправляет ссылку → ждёт ответ бота (или таймаут) → сохраняет в БД (SQLite,
таблицы `accounts` и `runs`) → пауза → следующий аккаунт. Последовательность
нужна, чтобы верно сопоставить ответ бота именно с той ссылкой, на которую
он ответил.

## Установка

```bash
cd tiktok-dashboard
npm install
cp .env.example .env
```

1. Получите `TG_API_ID` и `TG_API_HASH` на https://my.telegram.org/apps —
   впишите в `.env`.
2. Впишите в `.env` `TARGET_BOT_USERNAME` — username чужого бота без `@`.
3. Локально (не на сервере) выполните разовый логин:
   ```bash
   npm run login
   ```
   Введите номер телефона, код из Telegram и, если включена, пароль 2FA.
   Скрипт выведет строку — вставьте её в `.env` как `TG_SESSION`.
4. Задайте `DASHBOARD_USER`/`DASHBOARD_PASSWORD` в `.env`.
5. Запуск:
   ```bash
   npm start
   ```
   Дашборд будет на http://localhost:3000 (Basic Auth, если задан).
   Разовый ручной прогон рассылки без старта сервера: `npm run run-now`.

## Деплой (Railway, как и backend в этом репозитории)

1. Новый сервис на Railway, Root Directory = `tiktok-dashboard`.
2. Добавьте volume и примонтируйте, например, на `/data`; переменная
   `DB_PATH=/data/tiktok-dashboard.db`.
3. Переменные окружения — все из `.env.example`, значения из шагов выше.
   `TG_SESSION` получаете локальным `npm run login` и просто копируете сюда.
4. Build command: `npm install`, Start command: `npm start`.

## Использование

Откройте дашборд, добавьте ссылки на ваши TikTok-аккаунты через форму —
они начнут уходить целевому боту по расписанию (`SCHEDULE_CRON`, по
умолчанию раз в час). Кнопка «Отправить сейчас» запускает цикл рассылки
вручную, не дожидаясь расписания. На каждой карточке аккаунта видно
последний статус (ответ получен / таймаут / ошибка), текст ответа бота и
время отправки/ответа.
